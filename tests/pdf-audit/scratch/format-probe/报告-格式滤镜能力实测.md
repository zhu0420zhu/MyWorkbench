## 三、两个重点问题的回答

### 1. .wps/.et/.dps：内嵌 soffice 认不认？
**不认 Kingsoft/WPS Office 格式。** 滤镜注册表（`resources/tools/soffice/share/registry/*.xcd`）grep 证据：
- `writer.xcd`：`Extensions=wps` 只映射到 **Microsoft Works Document**（`writer_MS_Works_Document`，MediaType `application/vnd.ms-works`，DetectService `com.sun.star.comp.Writer.MSWorksImportFilter`，即 libwps，Flags=IMPORT，**无导出**）。这是 MS Works，不是金山 WPS。
- `calc.xcd`：`WPS_Lotus_Calc`（Lotus wk1-wk3）、`WPS_QPro_Calc`（QuattroPro）——同样是 libwps 系，与金山 .et 无关。
- 全注册表无 `kingsoft`、无 `et`/`dps` 扩展名映射。
- 实测补充：把真实 doc 内容改名为 .wps 后 `--convert-to pdf` **rc=0 成功**（35533 字节 PDF）——soffice 类型检测是**内容嗅探优先**，扩展名会被忽略，OLE 复合文档按实际内容识别。因此「doc 内容伪装的 wps」能开，真实金山 .wps（不同 CLSID/内部格式）会走 wps 的 detect service 嗅探失败，预期报 `source file could not be loaded`；此推论需真实 .wps 样本最终确认（当前环境无法生成）。
- **假阳性警告**：纯文本 dummy 文件（.et/.dps/.mobi/.azw3/.ofd）全部 rc=0「成功」——因为未知扩展名+文本内容会被纯文本滤镜静默兜底。任何「支持性探测」不能用文本 dummy，且产品侧要防这种 fallback 产出的乱码文档。

### 2. .doc/.xls/.mobi/.azw3/.ofd / .epub 支持情况
- **.doc**：全链路 ✓（导入→pdf/docx/odt + 回写 doc，`MS Word 97` 滤镜）。
- **.xls**：全链路 ✓（导入→pdf + 回写 xls，`MS Excel 97` 滤镜；还能升级转 xlsx）。
- **.mobi/.azw3**：注册表零命中（grep 到的 "mobi" 是 `mobilenumber` 误报），无导入滤镜，彻底不支持。
- **.ofd**：注册表零命中（"ofd" 命中是 `dateofdeath` 误报），无导入滤镜，彻底不支持。
- **.epub**：特殊——**能导出不能导入**（`--convert-to epub` 可用，作为输入则 rc=1 `source file could not be loaded`）。若产品有 epub 需求必须走第三方解析，不能靠 soffice。

## 四、对「转换-手术-回写」链路的结论
- docx/odt/rtf/doc（文本族）与 xlsx/ods/xls（表格族）、pptx/odp（演示族）全部支持「导入→转 OOXML/ODF→（手术修改）→回写原格式」，且回写 filter 名已实测确认（朴素转换即默认 OOXML filter，显式 filter 名亦有效）。
- 回写注意点：`--convert-to` 对「源格式=目标格式」同样执行重新导出（已实测 docx→docx 等 9 种），产物放在独立 outdir 即可避免源/输出冲突。
